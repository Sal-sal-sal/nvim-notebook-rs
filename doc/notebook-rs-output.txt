*notebook-rs-output.txt*  Navigating cell output

OUTPUT                                               *notebook-rs-output*

Enable textual inline output navigation: >lua
    require("notebook_rs").setup({
      cells_output_interacteable = true,
      nootbook_result = "nootbook",
      notebook = { output = { head = 30 } },
    })
<
The default for cells_output_interacteable is false.
The exact interacteable spelling is part of the configuration API.

When enabled, text results and tracebacks become real buffer lines below
that cell, with display prefixes concealed by Neovim.
Use j/k, h/l, Ctrl-f/Ctrl-b, /search, and visual selection normally.
Yanking only output strips the display prefixes from the register.
Source cursor positions and the viewport remain stable during redraws.
Output rows are protected from direct edits.
Edit and rerun the source cell to change its result.
Running or editing a cell while in its output targets that source cell.
Source undo and redo remain available.

Consecutive chunks from the same stdout or stderr stream share one OUTPUT block.
Carriage returns update the current line, so completed progress bars appear once.
Backspaces and common ANSI formatting or line-clear controls are handled for display.

By default only the first 30 text content lines of each cell are displayed.
The final row reports how many additional lines are hidden.
The limit is shared across that cell's streams, results, and tracebacks.
Headers and images do not count toward it.
Configure notebook.output.head in setup: >lua
    require("notebook_rs").setup({ notebook = { output = { head = 50 } } })
    -- To show all text:
    require("notebook_rs").setup({ notebook = { output = { head = false } } })
<
This affects navigable and virtual inline output, and updates open notebooks.
The separate bottom output panel retains its full text.

Cell output remains structured notebook data when saving with :write.
The original stream chunks and control characters are retained in saved notebooks.
Display rows are excluded from Python execution and stored source.
Changing source clears its stale output while retaining other cells.
PNG and JPEG images appear as virtual media below their source cells when
image.nvim is configured in a compatible terminal.
For Kitty, configure image.nvim with backend = "kitty" and
processor = "magick_cli".
Notebook charts use explicit cell sizes and window clipping on Retina too.
Charts temporarily hide when overlapping floating hints or completion menus.
They reappear when the popup moves away or closes, including which-key.
Images appear immediately below code, before potentially long text results.
Set image_output_position = "after_text" to restore text before images.
Set image_output = false to disable inline images, or image_max_height = 20
to choose the maximum reserved rows per image.
:NotebookOpenChart opens the first image of the current cell in the system
viewer; :NotebookOpenChart 2 opens the second.
This also works for saved notebooks and without image.nvim.
HTML remains a placeholder; :NotebookOpenArtifact opens generated artifacts.

Set cells_output_interacteable = false to restore virtual text output.
It affects only nootbook_result = "nootbook"; "window" and "hidden"
retain their existing display behavior.
Re-running setup changes the mode in open notebooks.
Start a new Neovim session after updating plugin source files.

See |notebook-rs-options| and |notebook-rs-keys| for other settings and keys.
A Russian walkthrough is available at docs/guide.ru.md in the repository.
